Copie-colle ce prompt à l’agent :

Teste complètement l’exécution des commandes terminal de Panda. Utilise réellement l’outil de commandes, ne simule pas les résultats et ne modifie aucun fichier du projet en dehors de /tmp.
 
Effectue les tests suivants, un par un :
 
1. Commande simple :
   pwd
 
2. Sortie standard :
   printf 'stdout-ok\n'
 
3. Sortie d’erreur :
   printf 'stderr-ok\n' >&2
 
4. Code de sortie réussi :
   printf 'exit-0\n'
   Vérifie que le code de sortie est 0.
 
5. Échec réel d’une commande :
   printf 'expected-failure\n'; exit 7
   Vérifie que l’agent signale l’échec avec le code 7 et ne relance pas automatiquement la commande.
 
6. Commande avec plusieurs lignes :
   printf 'line-1\nline-2\nline-3\n'
 
7. Commande avec sortie importante :
   for i in $(seq 1 100); do printf 'line-%s\n' "$i"; done
   Vérifie que la sortie reste lisible et complète ou correctement tronquée.
 
8. Commande avec délai court :
   sleep 1; printf 'after-sleep\n'
   Vérifie que la commande attend puis retourne correctement.
 
9. Commande en arrière-plan :
   (sleep 2; printf 'background-done\n') &
   printf 'background-started\n'
   Vérifie que l’exécution ne bloque pas inutilement.
 
10. Commande utilisant le shell courant :
    echo "$SHELL"
    Vérifie qu’il n’y a pas d’erreur du type ENOENT, terminal fermé, IPC fermé ou “not connected”.
 
11. Commande composée :
    cd /tmp && mkdir -p panda-command-test && printf 'created\n' > panda-command-test/result.txt && cat panda-command-test/result.txt
    Puis supprime uniquement /tmp/panda-command-test.
 
Pour chaque test, rapporte :
- la commande exécutée ;
- la sortie stdout ;
- la sortie stderr ;
- le code de sortie ;
- si le comportement est attendu ou non.
 
À la fin, donne un résumé :
- tests réussis ;
- tests échoués ;
- erreurs d’infrastructure éventuelles ;
- indique clairement si les commandes échouées ont été distinguées des erreurs du terminal.
